# Phase 1: Static Code Analysis

## Goal

Scan all 47 repos in TVSM-CS org, extract structured facts from code (endpoints, dependencies, service bus topics, ownership), and feed them into the knowledge graph **deterministically** — no LLM guessing.

**Timeline:** 2-3 weeks  
**Cost:** Zero ongoing (one-time scan + team review)  
**Accuracy improvement:** 80% → 90-92%

---

## What We Extract Per Repo

### Structural (who calls what)

| Data Point | Where We Find It | Languages |
|---|---|---|
| API endpoints exposed | Controller annotations, route definitions | Java, Node, .NET |
| HTTP calls to other services | HTTP client usage + URL patterns | Java, Node, .NET |
| Service bus topics published | Sender/producer code + config | Java, Node, .NET |
| Service bus topics subscribed | Listener/consumer code + config | Java, Node, .NET |
| Build dependencies | pom.xml, package.json, .csproj | Java, Node, .NET |
| Database connections | Config files, connection strings | All |
| Ownership | CODEOWNERS → git log fallback (top contributors) | All |
| Tech stack | Build file analysis (framework, language version) | All |
| Config/env vars | application.properties, appsettings.json, .env.example, web.config | All |

### Contextual (what does the code do)

| Data Point | Where We Find It | Cost |
|---|---|---|
| Service purpose | README.md first paragraph | Free — just read the file |
| Directory structure | Git tree (top 2-3 levels) | Free — already fetched |
| Key module descriptions | First comment/docstring per file in src/services/, src/controllers/ | Free — read first 5-10 lines |
| Domain vocabulary | Class names, function names, route names | Free — parse identifiers |
| Recent activity | Git log (last commit, active contributors, frequency) | Free — `git log` |bran
| Commit patterns | Who works on what parts of the code | Free — `git shortlog` |

## Scanner Architecture

```
src/
  analysis/                         ← NEW MODULE
    __init__.py
    scanner.py                      ← Main: clone repo → detect language → run extractors → output manifest
    extractors/
      __init__.py
      base.py                       ← Abstract base class for extractors
      java_spring.py                ← Spring Boot: @RequestMapping, RestTemplate, pom.xml, application.properties
      node_express.py               ← Express/NestJS: app.get(), axios/fetch, package.json
      dotnet.py                     ← ASP.NET: [HttpGet], HttpClient, .csproj, appsettings.json
      common.py                     ← Language-agnostic: Dockerfile, CODEOWNERS, git log, .env.example
      service_bus.py                ← Cross-language Azure Service Bus pattern detection
    models/
      __init__.py
      manifest.py                   ← Pydantic models for .service-manifest.yaml
    output.py                       ← Serialize manifest to YAML
    language_detector.py            ← Detect repo language from build files
  ingestion/
    manifest_ingest.py              ← NEW: reads manifests → writes to graph + vectors
```

## Language Detection Logic

```python
def detect_language(repo_files: list[str]) -> str:
    """Detect primary language from presence of build files."""
    if "pom.xml" in repo_files or "build.gradle" in repo_files:
        return "java"
    if "package.json" in repo_files:
        return "node"
    if any(f.endswith(".csproj") for f in repo_files):
        return "dotnet"
    if "pyproject.toml" in repo_files or "requirements.txt" in repo_files:
        return "python"
    return "unknown"
```

## Extraction Patterns

### Java (Spring Boot)

**Endpoints:**
```
@GetMapping("/users/{id}")
@PostMapping("/bookings")
@RequestMapping(value = "/api/v1/auth", method = RequestMethod.GET)
```

**HTTP calls (outbound):**
```
restTemplate.getForObject("http://tvsm-auth/validate", ...)
webClient.get().uri("http://notification-service/sms").retrieve()
@FeignClient(name = "payment-service", url = "${PAYMENT_URL}")
```

**Service bus:**
```
@ServiceBusListener(topicName = "booking-created", subscriptionName = "...")
serviceBusSenderClient.sendMessage(...)  // topic from config
```

**Config files to parse:**
- `src/main/resources/application.properties`
- `src/main/resources/application.yml`
- `pom.xml` (dependencies, Java version, Spring Boot version)

---

### Node.js (Express / NestJS)

**Endpoints:**
```
app.get('/api/v1/booking/:id', handler)
router.post('/create', controller.create)
@Get(':id')  // NestJS
@Post()      // NestJS
```

**HTTP calls (outbound):**
```
axios.get(`${process.env.AUTH_URL}/validate`)
fetch(`${NOTIFICATION_SERVICE}/api/v1/sms`, { method: 'POST' })
this.httpService.post(configService.get('PAYMENT_API') + '/charge')
```

**Service bus:**
```
const sender = sbClient.createSender('booking-created')
serviceBusClient.subscribe('payment-completed', { processMessage: ... })
```

**Config files to parse:**
- `package.json` (dependencies, scripts, name)
- `.env.example` (env var names)
- `src/config/` or `config/` directory

---

### .NET (ASP.NET Core)

**Endpoints:**
```
[HttpGet("users/{id}")]
[HttpPost("bookings")]
[Route("api/v1/[controller]")]
```

**HTTP calls (outbound):**
```
_httpClient.GetAsync($"{_config["AuthService:Url"]}/validate")
await client.PostAsync(paymentServiceUrl + "/charge", content)
```

**Service bus:**
```
await sender.SendMessageAsync(new ServiceBusMessage(...)); // topic from config
processor = client.CreateProcessor("booking-created", "subscription-name")
```

**Config files to parse:**
- `appsettings.json` / `appsettings.Development.json`
- `web.config`
- `*.csproj` (PackageReference, TargetFramework)

## Confidence Scoring

| Evidence Type | Confidence | Reasoning |
|---|---|---|
| Literal URL with known service name | **high** | `http://tvsm-auth/validate` — unambiguous |
| Env var name contains known service | **high** | `AUTH_SERVICE_URL` → tvsm-auth |
| Env var with generic name | **medium** | `EXTERNAL_API_URL` — can't be sure which service |
| Service name in code comment near HTTP call | **medium** | Comments can be stale |
| Build dep matches internal package | **high** | Direct code dependency |
| Topic name is literal string | **high** | `"booking-created"` — unambiguous |
| Topic name from env var / Key Vault | **low** | Can't resolve without runtime info |
| Inferred from file/folder naming | **low** | Naming conventions aren't guarantees |

## Implementation Tasks

### Task 1: Scaffold the analysis module
- Create `src/analysis/` package structure
- Define Pydantic models for manifest schema (`models/manifest.py`)
- Implement YAML serialization (`output.py`)
- Implement language detection (`language_detector.py`)

### Task 2: Build the Java/Spring Boot extractor
- Endpoint extraction (annotations → routes)
- HTTP client detection (RestTemplate, WebClient, Feign)
- Service bus patterns (listeners, senders)
- Config parsing (application.properties/yml)
- pom.xml parsing (dependencies, versions)

### Task 3: Build the Node.js extractor
- Endpoint extraction (Express routes, NestJS decorators)
- HTTP client detection (axios, fetch, httpService)
- Service bus patterns (createSender, subscribe)
- package.json parsing (dependencies, scripts)
- .env.example parsing (env var names)

### Task 4: Build the .NET extractor
- Endpoint extraction ([Http*] attributes, [Route])
- HTTP client detection (HttpClient, IHttpClientFactory)
- Service bus patterns (ServiceBusSender, CreateProcessor)
- .csproj parsing (PackageReference, TargetFramework)
- appsettings.json / web.config parsing

### Task 5: Build the common extractor
- CODEOWNERS parsing
- Git log analysis (top contributors as ownership fallback)
- Git activity extraction (last commit, frequency, active contributors)
- Dockerfile parsing (exposed ports, base image)
- README.md first paragraph extraction (for "purpose")
- Directory tree extraction (top 2-3 levels with annotations)
- Domain keyword extraction (from class/function/route names)

### Task 5b: Build the module description extractor
- For each file in src/services/, src/controllers/, src/routes/:
  - Read first 5-10 lines
  - Extract first comment block / docstring / JSDoc
  - If no comment, use file name + folder as description
- Output: key_modules list in manifest

### Task 6: Build the scanner orchestrator
- Clone repos (shallow clone, temp directory)
- Detect language → route to correct extractor
- Merge results from all extractors into one manifest
- Handle errors gracefully (one repo failing doesn't stop others)
- Rate limiting for GitHub API

### Task 7: Build manifest ingestion
- Read manifests from directory
- Update Service node properties in Neo4j
- Create/update DEPENDS_ON edges with evidence + confidence
- Update OWNED_BY edges
- Regenerate steering files (deterministic markdown)
- Re-embed updated steering in Qdrant

### Task 8: Test on 3-5 repos
- Pick repos of different languages (1 Java, 1 Node, 1 .NET if exists)
- Run scanner, inspect output manifests
- Verify graph updates
- Check chatbot answers improve

### Task 9: Full scan of all 47 repos
- Run scanner across entire org
- Generate all manifests
- Review output quality
- Share with senior for feedback

### Task 10: Team review process
- Decide: manifests live in tvsm-brain centrally OR PRed to each repo
- Create a simple review checklist for teams
- Teams correct/approve their manifests
- Re-ingest corrected manifests

## Risk & Mitigation

| Risk | Impact | Mitigation |
|---|---|---|
| Regex patterns miss edge cases | Some endpoints/deps not detected | Start with common patterns, iterate based on test results |
| GitHub rate limiting (47 repos × many files) | Scanner gets throttled | Shallow clones + local file scanning (no API per file) |
| Topic names only in Key Vault | Can't extract service bus topology | Mark as `confidence: low`, team fills in during review |
| Teams don't review manifests | Stale/wrong data persists | Start with 3-5 repos, prove value, then expand |
| .NET repos have different structure | Extractor doesn't work | Build .NET extractor last, after Java/Node prove the pattern |
